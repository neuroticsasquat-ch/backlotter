# NEU-306: React Router v7 SSR foundation (Cloudflare Workers) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate the frontend from a client-only SPA to React Router v7 **framework mode** with SSR on **Cloudflare Workers**, add an unauthenticated public layout + one SSR proof route (`/preview`), and keep every existing authed route working unchanged.

**Architecture:** One Cloudflare Worker serves the whole app. Public routes are server-rendered via React Router `loader`s under a `PublicLayout`. All existing routes move under a **client-only** pathless `SpaLayout` (a no-op `clientLoader` + `HydrateFallback`) so the server emits only a shell and the client hydrates into today's exact cookie + CSRF `/me` flow — no server session, no hydration mismatch. Deploy switches from Cloudflare Pages (static) to `wrangler deploy`.

**Tech Stack:** React 19 + TypeScript, `react-router` v7 framework mode (`@react-router/dev`), `@cloudflare/vite-plugin` + Wrangler, Vite 8, Tailwind v4, TanStack Query, Vitest + Testing Library + MSW. Runs in the container via `task`.

**Repo:** `upcoming-movies-frontend` · **Branch:** `tom/neu-306-frontend-react-router-v7-ssr-foundation` · **Spec:** `docs/specs/2026-06-22-neu-306-ssr-foundation-design.md`

**Blocks:** NEU-307 (SEO meta/OG + robots), NEU-310 (SSR film page), NEU-312 (SSR feed landing).

> **Commit/PR convention (frontend):** No per-step commits — implement, then run the full gate (`task format` on touched files → `task lint` → `task typecheck` → `task test`) and the user commits **once** (Conventional Commits + trailing `(NEU-306)`; keep the `🤖 Generated with Claude Code` footer, no `Co-Authored-By`) and opens **one** PR (single-PR decision). All commands run in the container via `task`; **Docker-only, no host Node/pnpm**; dependency changes need `task build` to sync the `node_modules` volume.

> **Why "scaffold from the official template" in Task 1:** the exact framework-mode + Cloudflare config files (tsconfig rootDirs, generated `Env` types, wrangler shape) track the current tooling. Rather than transcribe possibly-stale config, Task 1 generates the skeleton from `create-cloudflare` (authoritative) and we port our app onto it. App-specific files (`root.tsx`, `routes.ts`, entries, layouts, the proof route, tests) are given verbatim in later tasks.

export function ErrorBoundary({ error }: { error: unknown }) {
  let title = "Something went wrong";
  let detail = "Please refresh the page.";
